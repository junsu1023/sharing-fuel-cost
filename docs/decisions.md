# 결정 기록

기획에 명시되지 않아 사용자 결정이 필요한 항목과, 이미 결정된 내용을 기록한다.
`docs/brief.md`와 다르면 이 문서가 우선한다.

## 미결정

제안은 사용자가 확정하기 전까지 적용하지 않는다.

| ID | 질문 | 제안 | 영향 |
|---|---|---|---|
| D-1 | 잔여 금액을 누구에게 배정하는가? (예: 10,000원을 3명이 나누면 10원 남음) | 운전자가 잔여 금액을 부담해, 합계가 전체 기름값과 항상 일치하게 한다 | 정산 로직 |
| D-2 | 전체 기름값과 부담금은 몇 원 단위로 반올림하는가? | 1원 단위 반올림 | 정산 로직, 결과 화면 |
| D-3 | 탑승자의 이동 거리는 어떻게 정의하는가? 하차 위치도 입력받는가? | 하차 입력 없이, 경로상 탑승 위치부터 목적지까지의 거리로 한다 | 입력 화면, 정산 로직, 거리 조회 |
| D-4 | 전체 주행 거리는 탑승 위치를 경유한 거리인가? | 출발지 → 탑승 위치들(입력 순서) → 목적지 경유 거리로 한다 | 거리 조회, 입력 화면 |
| D-5 | 출발지, 목적지, 탑승 위치를 어떻게 입력받는가? 경로 조회에 좌표가 필요하면 주소 검색이 추가로 필요하다 | 카카오모빌리티 검증 결과를 보고 결정한다 | 입력 화면, 거리 조회 |
| D-6 | UI/UX 결과물은 Compose 코드만인가, Figma 시안도 필요한가? | Compose 코드와 Preview로 바로 구현한다 | UI 작업 방식 |
| D-7 | 앱 디자인의 분위기, 색상, 다크 모드 지원 범위는? | Material 3 기본, 라이트와 다크 모두 지원 | 테마 |
