# 결정 기록

기획에 명시되지 않아 사용자 결정이 필요한 항목과, 이미 결정된 내용을 기록한다.
`docs/brief.md`와 다르면 이 문서가 우선한다.

## 확인 필요

사용자 결정을 적용하면서 해석한 내용이다. 사용자가 다르게 정하기 전까지 이 해석을 따른다.

| ID | 해석 | 이유 |
|---|---|---|
| A-1 | 전체 기름값은 1원 단위로 반올림하고, 참여자별 부담금은 1원 미만을 버린다 | D-2의 반올림을 부담금에도 적용하면 20,000원을 3명이 나눌 때 6,667원씩 총 20,001원이 되어 D-1과 충돌한다 |
| A-2 | D-3의 "측정 시작"은 계산을 시작할 때를 뜻한다. 주행 중 위치를 측정하지 않는다 | 기획에서 실시간 GPS 추적을 제외했다 |
| A-3 | 경유 순서는 탑승 위치를 추가한 순서이고, 사용자가 바꿀 수 있다. 경로 최적화는 하지 않는다 | D-4에 순서 기준이 없다 |
| A-4 | 사용자에게 좌표를 입력받지 않고 주소나 지도 선택 결과를 내부에서 좌표로 변환한다 | 공식 문서 확인 결과 경로 API는 좌표만 받는다. D-5의 "좌표가 필요 없다"는 전제와 다르지만, 사용자 화면은 그대로다 |
| A-5 | 탑승자는 최대 5명으로 제한하고 자동차 길찾기 API를 쓴다 | 자동차 길찾기는 경유지 5개까지이며, 다중 경유지 API보다 무료량이 많고 초과 단가가 낮다 |
| A-6 | D-8은 추천안(지금은 앱에 포함, 공개 출시 전 서버 중계로 전환)으로 진행한다 | 사용자가 키를 `local.properties`에 등록해, 명시적 선택 대신 이 방식의 진행으로 해석했다 |
| A-7 | 유가는 앱을 열 때 하루 한 번 받고, 연료 종류 선택(휘발유, 경유, LPG)을 추가한다. 입력칸에는 1원 단위로 반올림한 값을 넣는다 | 평균 유가는 연료별로 다르고, 사용자 요청에 갱신 방식이 없다 |
| A-8 | 이동 거리 비례 분할에서 탑승자 거리 합이 전체 거리보다 길면 전체 기름값을 탑승자 거리 비율로 나누고, 운전자는 1원 미만 잔액만 낸다 | D-9를 그대로 적용하면 운전자 몫이 음수가 되어 실제 기름값보다 더 걷게 된다 |
