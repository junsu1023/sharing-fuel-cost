# 프로젝트 기획 원문

사용자가 제공한 기획 프롬프트 원문이다. 제목과 목록 서식만 정리했으며, 내용은 수정하지 않는다. 이후 변경된 내용은 `docs/decisions.md`가 우선한다.

---

기름값 계산 Android 앱 신규 프로젝트 구축

## 1. 역할

너는 숙련된 Android 개발자이자 소프트웨어 아키텍트다.
새로운 Android 프로젝트를 처음부터 설계하고 구현하라. 프로젝트 생성부터 아키텍처 구성, UI 개발, 기름값 계산 로직, 카카오모빌리티 경로 조회 연동, 테스트 및 빌드 검증까지 수행한다.
기존 프로젝트나 기존 코드가 존재한다고 가정하지 마라. 현재 작업 디렉터리에 파일이 있더라도 먼저 확인하고, 사용자의 명시적인 동의 없이 기존 파일을 삭제하거나 덮어쓰지 마라.

## 2. 앱의 목적

친구들과 자동차로 이동할 때 발생하는 기름값을 계산하고, 탑승자별 부담금을 정산하는 앱이다.
주요 정산 방식은 두 가지다.

1. 균등 분할: 운전자의 출발지부터 목적지까지의 전체 주행 비용을 참여 인원수로 나눈다.
2. 이동 거리 비례 분할: 운전자와 각 탑승자의 이동 거리를 기준으로 전체 주행 비용을 배분한다.

직선거리가 아닌 실제 자동차 도로 경로를 기준으로 거리를 조회하는 것이 목표다. 단, 자체 내비게이션이나 실시간 GPS 추적 기능은 개발하지 않는다.

## 3. 프로젝트 기술 스택

프로젝트가 없다면 Android 프로젝트를 새로 생성하라.

- 언어: Kotlin
- UI: Jetpack Compose
- 비동기 처리: Kotlin Coroutines 및 Flow
- 아키텍처: MVVM + MVI 기반의 단순하고 유지보수하기 쉬운 구조
- DI: Hilt
- 네트워크 통신: Retrofit 및 OkHttp
- 테스트: JUnit 기반 단위 테스트
- 빌드: Gradle Kotlin DSL

프로젝트 생성 시점의 안정적인 Android Gradle Plugin, Kotlin 및 라이브러리 버전을 조사해 서로 호환되는 조합을 선택하라. 버전을 임의로 최신이라고 가정하지 말고 공식 릴리스 정보를 확인하라.
향후 확장이 가능한 정도로 책임을 분리하되, 개인 개발자가 유지보수하기 쉬운 규모로 구성하라.

## 4. 첫 출시의 핵심 기능

### 4.1 기본 입력

- 출발지
- 목적지
- 탑승자별 탑승 위치
- 차량 연비(km/L)
- 리터당 유가(원/L)
- 정산 방식
- 참여자 정보

### 4.2 거리 조회

카카오모빌리티의 공식 SDK/API 문서를 조사하여 실제 자동차 주행 거리를 조회하는 기능을 구현하라.
먼저 다음 사항을 검증한다.

- 카카오내비 길찾기 SDK만으로 출발지와 목적지 사이의 주행 거리 데이터를 조회할 수 있는가?
- 별도의 Directions REST API가 필요한가?
- SDK/API별 인증 방식, 이용 조건 및 제휴 승인 여부는 무엇인가?
- API 응답에서 주행 거리를 어떤 데이터 필드와 단위로 제공하는가?

공식 문서에서 확인되지 않은 기능이나 메서드를 추측해 구현하지 마라.
거리 조회에 필요한 기능을 공식 SDK/API로 제공할 수 없는 경우, 수동 거리 입력 기능을 구현해 앱을 사용할 수 있도록 하라. 자동 거리 조회 기능은 교체 가능한 인터페이스로 분리하고, 실제 연동이 완료되지 않은 부분을 명확하게 표시하라.

### 4.3 기름값 계산

연료 사용량과 전체 기름값을 계산한다.

- 연료 사용량(L) = 주행 거리(km) / 연비(km/L)
- 전체 기름값(원) = 연료 사용량(L) × 리터당 유가(원/L)

정산 방식에 따라 참여자별 부담금을 계산하고, 원 단위 반올림 및 잔여 금액 처리 규칙을 적용한다.

### 4.4 결과 화면

- 전체 주행 거리
- 예상 연료 사용량
- 전체 기름값
- 정산 방식
- 참여자별 이동 거리
- 참여자별 부담금
- 결과 복사 및 공유

## 5. 구현 원칙

- 새 프로젝트의 디렉터리 구조와 패키지명을 명확히 설계한다.
- UI, 도메인 로직, 데이터 접근의 책임을 분리한다.
- 네트워크 호출을 ViewModel에서 직접 구현하지 않는다.
- 외부 API 인증키를 소스 코드에 하드코딩하지 않는다.
- 외부 API가 실제로 연결되지 않았다면 연동 완료라고 보고하지 않는다.
- 거리 조회 실패 시 수동 입력으로 대체할 수 있도록 한다.
- 단위 테스트를 통해 거리 변환 및 정산 계산을 검증한다.
- MVP 범위를 벗어나는 기능은 임의로 추가하지 않는다.

## 6. 작업 순서

1. 작업 디렉터리 확인 및 신규 프로젝트 생성
2. 기술 스택과 패키지 구조 구성
3. 앱의 핵심 화면과 UI 상태 구현
4. 기름값 계산 및 정산 도메인 로직 구현
5. 카카오모빌리티 SDK/API의 기술적 적합성 검증
6. 거리 조회 기능 및 수동 입력 대체 기능 구현
7. 정산 결과와 거리 조회 기능 연결
8. 단위 테스트 작성 및 실행
9. 빌드 및 오류 수정
10. 구현 결과와 외부 설정이 필요한 항목 보고

## 7. 최종 보고

다음 항목을 보고하라.

- 생성한 프로젝트 구조
- 구현한 화면과 기능
- 선택한 아키텍처 및 기술 스택
- 카카오모빌리티 SDK/API 검증 결과
- 실제 거리 조회 연동 성공 여부
- 빌드 및 테스트 결과
- 개발자 콘솔에서 직접 설정해야 하는 인증 정보
- 미구현 기능과 후속 작업

계획만 제시하고 종료하지 말고, 실행 가능한 환경에서는 실제 파일을 생성하고 코드를 작성하며 빌드 및 테스트까지 수행하라.
